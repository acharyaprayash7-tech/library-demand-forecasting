# Viva Questions & Simple Answers

## General

### Q1: Why is this an AI/DS project and not just a web app?

**A:** The core deliverable is a supervised regression model that predicts future demand from historical patterns. The web app is just the delivery layer for those predictions.

---

### Q2: Why did you use synthetic data?

**A:** Real library transaction data wasn't available or accessible for a student project. I generated realistic synthetic data with genuine trend, seasonal, and exam-period patterns so the ML problem would be meaningful rather than trivial.


---

# Technical / ML

### Q3: Why not just use random train/test split?

**A:** This is a forecasting problem. A random split could allow the model to train on data from months after the period it is tested on. That would cause data leakage and produce misleadingly optimistic results that may not hold up in real deployment.

---

### Q4: What is a lag feature and why did you use it?

**A:** A lag feature is a past value of the target used as an input. For example, last month's borrow count can be used to predict next month's demand. It captures recent demand patterns and is legitimately available at prediction time.

---

### Q5: Why did you compare three models instead of just using the best one?

**A:** I compared Linear Regression, Random Forest, and XGBoost to establish a baseline and evaluate different modeling approaches. Linear Regression provided a simple baseline, while Random Forest and XGBoost were used to capture more complex nonlinear relationships. I then compared their test performance before selecting the final model.

---

### Q6: Which model did you select?

**A:** I selected the Random Forest Regressor because it achieved the lowest test RMSE among the three evaluated models.

**Random Forest Test Results:**

- MAE = **6.1634**
- RMSE = **9.4191**
- R² = **0.7079**

---

### Q7: What does an R² of 0.7079 mean here?

**A:** It means the Random Forest model explains approximately **70.79% of the variation** in next-month demand using the available features. The remaining variation can come from noise and factors that are not captured by the current dataset.

---

### Q8: What would you do differently with real data?

**A:** I would retrain the model using actual historical borrowing records, validate the exam and seasonal patterns against the real academic calendar, and add more detailed features such as department-wise student enrollment, course demand, syllabus information, and actual inventory data.


---

### Q10: How did you avoid unrealistic random data?

**A:** I did not generate completely independent random numbers for every row. Each book was given a base popularity and trend characteristics, along with category-specific and exam-period effects. Poisson-distributed noise was then added to create realistic variation in borrowing demand.

---

### Q11: Why is the dataset called synthetic?

**A:** Because the data was artificially generated by the project rather than collected from a real library. It was created to simulate realistic library borrowing behavior for academic machine learning experimentation.

---

### Q12: Why did you use a fixed random seed?

**A:** I used a fixed random seed of **42** so that the synthetic dataset can be reproduced consistently. Running the data-generation process again with the same seed produces the same dataset.

---

# Model Evaluation

### Q13: What evaluation metrics did you use?

**A:** I used three main regression metrics:

1. **MAE — Mean Absolute Error**
2. **RMSE — Root Mean Squared Error**
3. **R² — Coefficient of Determination**

---

### Q14: What is MAE?

**A:** MAE represents the average absolute difference between the actual demand and predicted demand. A lower MAE means the predictions have smaller average errors.

---

### Q15: What is RMSE?

**A:** RMSE measures the prediction error and gives more importance to larger errors. A lower RMSE indicates better prediction performance.

---

### Q16: What is R²?

**A:** R² indicates how much of the variation in the target variable is explained by the model. A higher R² generally means the model explains more of the observed variation.

---

### Q17: Why did you use RMSE for model comparison?

**A:** RMSE was useful because it gives greater weight to larger prediction errors. In demand forecasting, large prediction errors can be important because they may result in significant inventory shortages or excess stock.

---

# Feature Engineering

### Q18: What is your target variable?

**A:** The target variable is the **next month's borrowed count**, which represents the future demand that the model is trained to predict.

---

### Q19: What are the main features used by the model?

**A:** The model uses 21 features, including:

- Previous borrowing demand.
- Rolling average demand.
- Month index.
- Exam-period indicator.
- Holiday indicator.
- Semester information.
- Available copies.
- Reservation count.
- Renewal count.
- Publication year.
- Encoded book categories.

---

### Q20: What is a rolling average feature?

**A:** A rolling average calculates the average demand over previous observations. In this project, `rolling_3_avg_borrowed` represents the recent three-observation average demand and helps capture the recent demand trend.

---

### Q21: What is data leakage?

**A:** Data leakage happens when information that would not be available at prediction time is accidentally used to train the model. It can make model performance look better during testing than it would be in real-world use.

---

### Q22: How did you prevent data leakage?

**A:** I used historical lag and rolling features, maintained chronological ordering, and used a time-aware train/test split. Future test-period observations were not randomly mixed into the training data.


---

# Time-Aware Split

### Q23: What is a time-aware train/test split?

**A:** A time-aware split separates the data chronologically. Earlier observations are used for training and later observations are used for testing.

**Example:**

Past Data → Training

Future Data → Testing

This better represents a real forecasting scenario.

---

### Q24: What was your split date?

**A:** The split date used in the project was **2024-01-01**.

The evaluation data contained:

- **2,640 training rows**
- **600 testing rows**

---

### Q25: Why is chronological splitting important for forecasting?

**A:** Because when we forecast the future, we only have access to past information. A chronological split simulates this real-world situation and helps provide a more realistic evaluation of the model.

# Inventory Recommendation

### Q31: How does your inventory recommendation work?

**A:** The system compares predicted demand with available copies.

The calculation is:

**Additional Copies = max(0, ceil(Predicted Demand - Available Copies))**

If current stock is already sufficient, the recommendation is zero.

---

### Q32: Is the system automatically telling the library to purchase books?

**A:** No. The recommendation is only a **data-driven decision-support suggestion**. The final inventory or purchasing decision should consider factors such as budget, shelf capacity, supplier availability, and library policies.

### Q36: Explain your project in one minute.

**A:** My project is a Library Book Demand Forecasting System using machine learning. It uses historical borrowing data along with factors such as previous demand, rolling demand, examination periods, holidays, reservations, renewals, inventory, and book categories to predict next-month book demand.

I compared Linear Regression, Random Forest, and XGBoost using a chronological train/test split. Random Forest achieved the lowest test RMSE of **9.4191** with an R² of **0.7079**, so it was selected for the final prediction pipeline.

The prediction is then displayed through a Streamlit web application, which also provides book analysis, analytics, demand classification, and inventory recommendations.

The dataset is synthetic and was created specifically for academic demonstration.
